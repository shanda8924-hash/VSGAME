# VSGAME マップ・UIブラッシュアップ設計案

2026-09-05 / ユーザー承認済み。追加依頼で宝物庫・鍛造・装備絵・Drop・MAP全面描画へ拡張。
コード/新規素材を接続済み。起動時の型推論エラーを修正し、主要画面はGodot/Vulkanで確認済み。
全MAP・長時間等の残検証は実装記録を参照。
採用仕様はgame_specification.md §23/34/35/37、現在状態はdocs/royal_visual_implementation.mdを参照。

## 1. 推奨コンセプト

**「朽ちた王国の地下を踏破する、鮮やかな16bit遺跡ファンタジー」**

石・古い金属・紫晶・火の明かりを共通モチーフにする。敵を見分け、回避し、
遺物と大技で大群を突破する気持ちよさを画面の中心に置く。
背景は重厚、キャラクターは明快、攻撃は鋭く、報酬は魅力的にする。
既存の3MAP、職業、状態異常、装備、完成大技、ボス後4枠ショップを前提とする。
廃止した属性・Fusionを復活させる提案ではない。

## 2. 確認した現状と改善ポイント

- 実コード: HUDはRetroHUDStyle、ショップはPixelUIStyleを使用。配色と枠の体系が分かれている。
- HUD共通部品に連続グラデーション、複数半透明矩形のGlow、光沢表現がある。
  ピクセル表現を揃える際には段階色・エッジの陰影へ置き換える候補。
- ShopScreenの商品は複数行のButton.textで構成され、商品画像と情報の強弱を付けにくい。
- 16pxタイル、戦闘地形、9-slice金枠とカテゴリ画像など再利用できる資産がある。
- 保存済みmap_region_pillar_field.pngでは床の切替が強い矩形・格子として見え、
  通常床と戦闘地形の馴染みを改善できる。ショップ画像では文字の塊が商品視認の中心になっている。
- 保存画像には旧Fusion UIが残る。現行UIの実機画像として断定しない。
  実装前に最新RuntimeのHUD/戦闘/各Modalを撮り直して比較基準とする。
- §34/35には廃止済み属性・Fusionの旧記述が残る。設計基準は現コードと§36/37を優先。

今回は現物に基づく独自提案。市場調査や他作品との優劣比較は行っていない。

## 3. 共通アートルール

### ドット密度・形

- 基本タイル16×16、UIアイコン16×16、重要装備の絵32×32を基本にする。
  柱や祭壇など大型オブジェクトは同じドット密度の複数タイルとして描く。
- Nearest拡大を基本とし、異なる密度の画像を混ぜない。カメラの動きや当たり判定を
  ピクセル整列目的で変更せず、描画上の整列方法を先に検証する。
- 左上光源、輪郭は黒一色でなく濃紺・濃茶。色面で立体を作り、細かい点描を増やしすぎない。
- UIの枠は1〜2論理pxの階段状陰影。角飾りは重要なパネルに限定。
- 全画面8色には制限しない。小物は4〜8色、素材群は共有パレットを使う。

### 配色と役割

|役割|候補色|用途|
|---|---|---|
|最暗部|#151B29|壁の奥・文字輪郭|
|背景石材|#343D4B / #596170|床・壁。床は細部の明度差を弱くする|
|UI地|#202638|文字が背景に埋もれない濃紺|
|古金|#9D7138 / #D6A957|選択・価格・重要な縁取り|
|文字|#F2E6CD|主文。補助文は一段暗い灰紫|
|生命|#E66D75|HP・被弾|
|技|#72C9CB|クールダウン・使用可能|
|危険|#F17C4C|敵の予兆・危険床の縁|

色だけで意味を伝えず、アイコン・形・文字を併用する。レア度や状態色が同系統でも、
危険の輪郭・報酬の台座・UIのラベルで区別できるようにする。
背景の彩度と白色面積を抑え、最高輝度を攻撃の瞬間と操作対象に残す。

## 4. マップ

### 3MAPの見分け

|MAP|素材と色|記憶に残る場所|戦闘面での狙い|
|---|---|---|---|
|忘却の地下回廊|青灰の石、苔、琥珀の灯り|崩れた紋章門・古い噴水|道と壁が読みやすく、探索の基本が分かる|
|紫晶の深層|暗い青紫岩、局所的な青緑結晶|巨大な晶洞・断ち切られた採掘跡|柱と回り道を景観として理解できる|
|終焉の炉心|煤けた石、鉄、橙赤の炉光|中央炉・巨大な歯車壁|大群とボスへ向けて圧力が高まる|

単なる全体Tint変更にせず、壁上端・床材・大型目印を変える。最初はMAP1だけ完成させる。

### 床・壁・装飾

- 床は静かな基本タイルを主にし、割れ・苔・欠けは少量の塊で配置する。
  全床に目立つ格子線を入れず、同じタイルの繰り返しを弱める。
- Arena/Pillar/Chokepoint/Hazardの機能は維持し、外周に移行タイルを入れて床材を馴染ませる。
- 壁は上端の光、垂直面、足元影の3段で高さを表す。柱は根元が見えて迂回可能範囲が読める形にする。
- 装飾は壁際と部屋の焦点へまとめ、中央の回避レーンを空ける。装飾と衝突物の形を区別する。
- 新たな経路障害物を大量追加しない。まず既存地形の見た目を改良する。

### 探索の案内

- 各エリアに「噴水の部屋」「結晶門の先」と呼べる目印を置く。
- ボス門は通常扉と別シルエット。封印中・解放済み・入場可能を形と紋章で区別する。
- 宝箱は閉/開で形を変え、操作範囲内だけE/Controller案内を表示する。
- ミニマップは追加候補。初期範囲は訪問済み経路・現在地・発見済み目的地まで。
  常時全アイテムを表示せず、詳細地図は別画面。新機能なので外観刷新とは別工数で扱う。
- 環境の動きは松明・少数の結晶・炉に絞る。暗さだけで雰囲気を作らず、危険は常に読めるようにする。

## 5. UIの全体設計

### 共通部品

濃紺パネル、古金の段差枠、明るい文字、金の三角カーソルを共通化。
通常/選択/押下/購入不可を背景・輪郭・アイコンで区別。選択時の全体点滅は使わない。
既存のshop_frame.pngとカテゴリ画像を実寸検証し、良いものを採用する。
DotGothic16は候補だが、和文説明文を実解像度で比較して可読性を優先する。
16px原寸または整数倍を基本に、13px等への縮小を避ける。長い説明は詳細欄に分ける。

### 戦闘HUD

|位置|情報|優先順位|
|---|---|---|
|左上|職業アイコン、HP、Lv/細いXPゲージ|HPを最も読み取りやすくする|
|上中央|現在の目的。ボス中はボスHPへ切替|MAP名より次にすべきこと|
|右上|所持Gold、地図ボタン。ミニマップ採用時はここ|常時小さく配置|
|下中央|特殊攻撃/居合のアイコン、キー、残り待機時間|READYを短く明瞭に|
|右下|完成大技・装備への入口、Comboの一時表示|詳細は戦闘画面へ展開しない|

画面中央の60〜70%程度を戦闘視認域として空ける案。HUD縮尺は設定できるよう検討する。
常時説明文を減らし、目的は「封印解除 244 / 420」→「ボス門へ」のように短くする。
「救済まで」は「時間解放まで」へ言い換え、小さな補助表示にする。時間条件は変えない。
侵攻は短い通知の後、小さな状態表示へ。画面全体を長時間強く着色しない。

### 選択・管理画面

|画面|構成|
|---|---|
|レベルアップ|同幅の3択。アイコン→名称→主効果→詳細。例「攻撃力 +10%」を最大の情報にする|
|完成大技|大技の絵、発動条件、主効果、現在Lv。取得時に何が変わるかを短く表示|
|ショップ|既存4枠を2×2。各枠に商品絵・名前・主効果・価格。所持金と購入後残高を同じ視線上に|
|装備|所持品一覧と選択品の詳細を分け、現装備との比較を固定位置へ。増減は色と±を併用|
|合成|既存3スロットと結果予告を視線順に配置。素材消費と結果を確定前に明示|
|ポーズ|再開を最上位、設定/装備/終了を統一ボタンで整理|
|タイトル/キャラ選択|地下遺跡の絵と共通枠。職業の攻撃傾向・状態・特殊技を同じ順序で表示|
|結果|踏破MAP、完成したbuild、主な戦績、再挑戦を整理。数値を全部同じ大きさで並べない|

ショップの価格・カテゴリ数・補充・リロール仕様は維持。購入不可でも詳細を読める選択状態を用意し、
不足Goldを示す。商品補充後も選択位置を維持し、買い物中にカーソルが飛ばないようにする。
商人の新規キャラ絵は初期必須にせず、既存小物・棚・灯りで店らしさを作る。
全ModalはKeyboard/Controllerで到達・確定・取消・復帰まで完結させる。

## 6. 性能・検証の条件

- 現在の性能問題は原因未確定。外観変更の前に同一条件の画像/性能baselineを保存する。
- 地形は既存TileMapLayer/atlasを中心に組み、装飾ごとのprocessや大量の常時particleを増やさない。
- UI枠は既存9-slice等を活用。全画面blur、多数の半透明重ね、無制限Light2D追加は採用しない。
- UI値更新は変化時、既存signal中心。見た目の刷新に戦闘ロジック変更を混ぜない。
- 同じseed/build/敵数/cameraでbefore/afterを比較。vsync無効、FPS制限なしでavg/p95/max、draw call、VRAMを記録。
- 性能受入の暫定目標: 同条件p95悪化が0.2msまたは10%の大きい方以内。
  繰り返し計測でばらつきと区別し、超過した演出は見直す。これは未承認の提案値。
- 1280x720 / 1600x900 / 1920x1080、UI拡大時、日本語の長い説明、金額桁増加を確認。
- 通常戦闘・大群・侵攻・ボスで、敵/予兆/Dropが背景と混ざらないことを実機確認。
- 壁の見た目と衝突形状、目的地への到達、全Modalの入力復帰を確認する。

## 7. 推奨する進め方

1. 最新画面の採取と、共通色/ドット密度/文字/枠の小さなスタイル見本を作る。
2. MAP1の一画面とHUDの見本を作り、敵32体・攻撃・Dropがある状態で比較する。
3. 同じルールをレベルアップと4枠ショップへ適用。ここまでを最初の完成範囲にする。
4. 採用した見た目でMAP1全域、装備/合成/ポーズ/タイトル/結果へ展開する。
5. MAP2/3の素材差分へ展開。ミニマップ等の新機能は別途判断する。

最初の承認対象は「MAP1 + HUD + レベルアップ + ショップ」の統一方向。
全素材の一括作り直しに入る前に、この範囲で読みやすさ・世界観・性能を確かめる。
