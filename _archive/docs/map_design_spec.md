# MAP設計仕様 (2026-08-30)

`docs/codex_task_map_and_rhythm.md`のPart Aで求めた地形の、**具体的な設計**。
Codexはこの仕様に沿って`systems/dungeon_generator.gd`の生成ロジックを組み直す。

---

## 0. 設計の基準となる実寸(必ず前提にすること)

| 項目 | 値 |
|---|---|
| 1セル | 16px × `TILE_RENDER_SCALE 2` = **32px** |
| マップ全体 | 100×100セル = 3200×3200px |
| **画面表示域** | 1600×900 ÷ カメラzoom 1.5 = 1067×600px = **約33×19セル** |
| プレイヤー当たり半径 | 20px(約0.6セル) |
| 敵 当たり半径 | 14px(約0.45セル) |
| 敵の出現距離 | プレイヤーから220〜480px = 7〜15セル(画面端付近) |
| 敵の同時上限 | MAP1/2/3で 32 / 40 / 48 |

**すべての地形サイズは「33×19セルの画面にどう映るか」で決めている。** この数字を
無視してサイズを変えると設計意図が壊れる。

### 現状の問題

`MIN_ROOM_SIZE 8` / `MAX_ROOM_SIZE 14`は、画面幅33セルに対して**1/4〜1/2**しかない。
部屋が空間の単位としてプレイヤーに認識されず、常に「部屋2〜4個+通路」がまとめて
視界に入るため、どこにいても同じ景色に見える。**部屋サイズの見直しが地形設計の前提**になる。

## 1. ゾーン制へ移行する(均一な部屋をやめる)

12個の均一な部屋を廃し、**役割ごとにサイズの違うゾーン**を生成する。
サイズは「画面に対する占有率」から逆算している。

| ゾーン | サイズ(セル) | 画面占有 | MAP1個数 | 戦闘上の役割 |
|---|---|---|---|---|
| **大広間** Arena | 28×20 | ほぼ全画面 | 2 | 大群を一掃する爽快感の場。範囲攻撃が映える。**surge中は四方から来るため最も危険** |
| **柱林** Pillar | 22×18 | 約2/3画面 | 4 | 柱を縫って敵の直線追跡を切る。**操作が上手いほど得をする**避難先 |
| **隘路** Choke | 幅6 × 長さ14〜20 | 細長 | 4 | 敵を一列に絞る。貫通・直線攻撃が輝く。囲まれると逃げ場がない |
| **危険地帯** Hazard | 14×12 | 約1/3画面 | 3 | 継続ダメージ。近道かつ**敵にも効く戦術資源** |
| 連絡路 Corridor | 幅4 | — | 接続用 | 既存の`CORRIDOR_WIDTH 4`を流用 |

床面積は現在の約14.5%から**約35%**に増える。歩ける面積が増えることでカイティングの
自由度が上がる。壁が減りすぎて構造が消えないよう、ゾーン間は必ず壁で仕切ること。

### 大広間 Arena

- 28×20セル(896×640px)。画面幅の約85%を占め、入った瞬間に「開けた」と分かる。
- **内部に障害物を置かない。** ここは範囲攻撃と画面一掃の快感のための場所。
- 各MAPに2箇所。うち1箇所はボス領域の手前に置き、決戦前の準備地点にする。

### 柱林 Pillar

- 22×18セル。**柱は2×2セル(64px)**。16bitのドット絵として塊が読めるサイズ。
- **柱の間隔は3セル(96px)を基本**とする。プレイヤー直径40px・敵直径28pxに対し
  余裕を持って通れ、かつ敵の直線追跡は確実に切れる。
  - 2セル(64px)まで詰めると通れるが窮屈。**1セル以下は絶対に作らないこと**(挟まる)。
- 柱の配置は格子状にせず、**わずかにずらす**。整然と並ぶと迷路ではなく倉庫に見える。
- **柱は`collision_layer = 1`(壁と同じ)に置くこと。** 敵の`collision_mask = 1`が
  そのまま効くため、敵も柱を回り込む。追加実装は不要のはず。実機で確認すること。

### 隘路 Choke

- **幅6セル(192px)**。画面幅33セルに対し約1/5で、明確に「狭い」と読める。
  - 4セル以下にしないこと。敵の同時上限48体が詰まると通り抜け不能になり、
    理不尽な死につながる。
- 長さ14〜20セル。長すぎると移動が退屈になる。
- 出口を2方向以上確保する。**行き止まりの隘路を作らないこと**(下記2-3参照)。

### 危険地帯 Hazard

- 14×12セル。床の見た目で危険と分かること。
- **ダメージは継続式(DoT)。最大HPの2〜3%/秒程度。** 入った瞬間の即死・大ダメージは
  作らないこと(レビュー調査で最も嫌われた「理由のわからない死」に直結する)。
- **敵にも同じダメージを与えること。** これが最重要。危険地帯が「避ける場所」から
  「敵を誘い込んで削る戦術資源」に変わり、プレイヤーの選択肢が1つ増える。
- 完全な迂回路を必ず用意する。危険地帯を通らないと進めない構造にしないこと。

## 2. マップ全体の構造

### 2-1. 背骨と枝(critical path + branches)

現在の「部屋を順に繋ぐ」方式をやめ、以下の構造にする。

```
スタート ─ 背骨(ゾーン6〜7個を直列) ─ ボス領域
              │      │      │
              枝     枝     枝     ← 報酬(宝箱・祭壇)はここに置く
```

- **背骨には報酬を置かない。** 進むだけなら最短で行ける。
- **報酬は必ず枝の先に置く。** 4つの宝箱、属性祭壇1、生命祭壇1は全て枝に配置する。
- これにより「寄り道して強くなるか、先に進むか」がプレイヤーの選択になる。
  現在は最遠部にボスがあるだけで、経路上の意思決定が存在しない。

### 2-2. ゾーンの並びを単調にしない

背骨に同じ種類のゾーンを**連続させないこと**。大広間→大広間のような並びは
「さっきと同じ場所」に見える。最低でも1つ挟む。

### 2-3. 退避地形の到達性(理不尽さを防ぐ最重要制約)

**マップ上のどの地点からも、1画面(33セル)以内に柱林または隘路が存在すること。**

surge(侵攻フェーズ)中に大広間の中央で四方から囲まれ、逃げ場が1画面以上先にしかない
状況は、プレイヤーから見て「回避不能な死」になる。レビュー調査で最も嫌われる形。

**生成後にこれを自動検証すること。** 満たさない配置が出たら再生成する。

### 2-4. 行き止まりの禁止

完全な袋小路を作らないこと。枝の先端(報酬地点)は例外として許容するが、
その場合**枝の長さを8セル以内**に抑え、逃げ帰れる距離にすること。

生成後に到達性検証(全床セルがスタートから到達可能か)を自動で行うこと。

## 3. MAPごとの差(絵は共通、構成で差をつける)

見た目はHUDのレトロ16bitパレットで3MAP共通とし、**ゾーン構成比で難度と性格を変える**。
これにより生成する画像量を増やさずに進行の実感を作る。

| | 大広間 | 柱林 | 隘路 | 危険地帯 | 性格 |
|---|---|---|---|---|---|
| **MAP1** | 2 | 4 | 3 | 1 | 教える。退避先が多く、危険地帯は1つだけ。初見でも死ににくい |
| **MAP2** | 2 | 3 | 4 | 3 | 混ぜる。危険地帯が戦術資源として意味を持ち始める |
| **MAP3** | 3 | 2 | 5 | 4 | 追い込む。大広間は増えるが退避先が減り、開けた場所が本当に危険になる |

MAP3で大広間を増やすのは、終盤のビルドが完成した状態で**画面一掃の快感を最大化**する
ため。同時に柱林を減らすことで、その快感に見合った緊張を残す。

## 4. 侵攻フェーズ(surge)との噛み合わせ

surgeの仕様は`docs/codex_task_map_and_rhythm.md` Part Bを参照。地形側の要件のみ記す。

- surge開始時、**プレイヤーが現在いるゾーンの種類によって体験が変わること**が設計の狙い。
  - 大広間 → 四方から包囲される。最も危険だが、範囲攻撃が決まれば最も気持ちいい。
  - 柱林 → 柱で敵の列を切りながら捌ける。腕の見せどころ。
  - 隘路 → 一列に絞れる。強いが、両側から来ると詰む。
  - 危険地帯 → 敵をまとめて焼ける。ただし自分も削れる。
- **surge中に新しい地形を生成しないこと。** 足元が変わるのは理不尽。
- surge開始の合図は、プレイヤーが**退避先へ移動する時間**を確保できるだけ早く出すこと
  (開始1.5〜2秒前に予兆)。予兆なしで即座に密度が跳ねるのは「見えない敵に殺された」
  という感想に直結する。

## 5. 見た目 — タイル画像は作成済み。新規生成しないこと

**タイルセットは既に完成している。Codexは新しく描き起こさないこと。**

| ファイル | 内容 |
|---|---|
| `assets/tiles/dungeon_tileset_retro.png` | 実タイルセット。16x16タイル / 8列×6行 = 128×96px |
| `assets/tiles/_preview_tileset.png` | 目視確認用の8倍拡大プレビュー(グリッド線付き) |
| `tools/generate_dungeon_tileset.ps1` | 生成スクリプト。色・密度の調整はここを直して再実行する |

HUD(`ui/common/retro_hud_style.gd`)と同一パレットで作成済み。光源は左上に統一
(HUDパネルのベベルと同じ方向)。

### atlas座標(列, 行)

```
(0,0)-(3,0) 大広間 床 v0-3          (4,0)-(7,0) 危険地帯 床 v0-3
(0,1)-(3,1) 柱林 床 v0-3            (4,1)-(7,1) 隘路 床 v0-3
(0,2)-(3,2) 壁 v0-3                 (4,2)-(7,2) 壁(bronze装飾) v0-3
(0,3)-(1,4) 柱A (2x2)               (2,3)-(3,4) 柱B (2x2)
(4,3)-(5,4) 危険地帯 噴出口 (2x2)   (6,3)-(7,4) 瓦礫 (2x2)
(0,5)-(7,5) 小物: 小瓦礫 / ひび / bronze格子 / 苔 / 危険地帯の縁 / 床標 / 骨 / 壁際の傷
```

床の各変種(v0-3)はランダムに散らして使う。1種類だけ敷き詰めると継ぎ目が
規則的に並んで見えるため、必ず4変種を混ぜること。

### 4種の床を「組積パターン」で描き分けてある(重要)

画面には常に複数ゾーンが同時に映るため、**色相ではなく石の積み方**で区別している。
色だけで分けると暗い画面では判別できない。

- **大広間** = 16x16の1枚板。最も情報量が少なく「開けている」と読める
- **柱林** = 8x8の格子(縦横の継ぎ目が揃う)
- **隘路** = 馬目地(段ごとに縦継ぎ目が半分ずれる)。**柱林と揃えると同じ格子に見えるので絶対にずらす**
- **危険地帯** = 紫の亀裂。唯一意図的に目立たせている床

`(4,5)`の「危険地帯の縁」は通常床→危険床の境界に敷き、危険域の輪郭を明示するのに使う。
危険が読めないことの害は、地形が少し騒がしくなる害より大きい。

### 地形側から出す残りの要求

- **4種のゾーンが色と模様で一目で区別できること。** 形だけの区別に頼らない
  (画面には常に複数ゾーンが映るため、形では判別できない)。
- **地形は背景に徹すること。** 床の模様が主張しすぎると、その上に乗る敵・
  エフェクト・戦利品が読めなくなる。HUDのパレットのうち暗い側
  (`void #241f45` / `void-deep #150f30`)を床の基調にし、明るい`bronze`系は
  縁取りやアクセントに留める。
- **危険地帯だけは例外的に目立たせてよい。** 危険が読めないことの害の方が大きい。

## 6. 検証(生成器の自動テスト)

`docs/codex_task_map_and_rhythm.md`の検証項目に加え、生成器側で以下を自動検証すること。

1. 全床セルがスタート地点から到達可能(孤立領域がない)。
2. 任意の床セルから33セル以内に柱林または隘路が存在する(2-3の制約)。
3. 柱の間隔が1セル以下になっている箇所が存在しない。
4. 隘路の幅が4セル未満になっている箇所が存在しない。
5. 危険地帯を通らずにボス領域へ到達できる経路が存在する。
6. 背骨に同種ゾーンの連続がない。
7. 報酬(宝箱4・祭壇2)が全て枝に配置され、背骨上にない。

**シード値を変えて100回程度生成し、上記が毎回成立すること**を確認する。
1回でも失敗するなら、その配置はプレイヤーに理不尽な体験を与える。
