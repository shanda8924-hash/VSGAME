# 遊びの骨組みの作り直し — 設計メモ（2026-10-31）

ユーザーの評価：「楽しくない」。内訳は次の4つ。見た目（VFX・アイコン・UI・ドロップ・戦場）は2026-10-31までに揃えたので、
ここからは**ループそのもの**を直す。この文書は、ローカルのCodex／Claude Codeが「Phase 1から」で着手できるように、
原因の所在（コード・データ）と打ち手、順番、検証の基準をまとめたもの。数値は出発点であり、遊んで調整する前提。

| 症状 | 一言 |
|---|---|
| 退屈 | 敵が弱くて緊張がない。やることが移動だけ |
| 単調 | 5分がずっと同じ。終盤ボスまで山場がない |
| 分かりにくい | 何を目指せばいいか、何が得なのか見えない。新技の発動条件と中身がカードから読めない |
| 育成がない | 1ダンジョンでキャラが終わる。何個も挑戦して強くなっていく手応えがない |

目指す体験：**「攻撃を当てるたびに雷が落ちる」を取ったら、次は攻撃速度か連撃で雷を増やそう**——と
プレイヤー自身が考えてビルドを組み、ステージをまたいで育っていく。

---

## 現状の所在（なぜそうなっているか）

- **緊張**：`data/difficulty/five_minute_survival.json`は0→210秒で間隔1.0→0.45秒・1回3〜4→8〜10体の単調増加。
  `data/maps/exploration_run.json`の`maps[].enemy_hp_multiplier 0.38`・`enemy_move_speed_multiplier 0.65`・`enemy_damage_multiplier 0.7`。
  波（サージ）は`surge.enabled: false`で止まっている。敵は直進のみ（floor_onlyでChase直進）。回復は75/150秒の箱とショップ。
- **山場**：上記のとおりサージ無効。240秒のボス以外に「区切り」が無い。HUDの時計は残り時間だけ。
- **スキルの読めなさ**：`data/upgrades/*.json`は`display_name / description / effect_type / value`だけで、
  発動条件・タグ・相性のデータが無い。`entities/player/survival_upgrade_effects.gd`の残影追撃は`_echo_cooldown 0.6秒`、
  雷光連鎖は`_chain_cooldown 0.7秒`で、**攻撃速度や連撃を上げても発動回数が増えない**（シナジーが構造的に無い）。
  レベルアップ（`ui/level_up_select/`）は動く比較を出すが、「いつ・何が起きるか」は文章頼み。
- **育成**：`components/equipment_component.gd`の`_on_run_ended`で装備を全消去。`SaveManager`に残るのは
  `meta_currency`（継承の欠片）・`unlocked_character_ids`・`unlocked_survival_maps`・`best_survival_seconds`・`deepest_cleared_floor`。
  職業の熟練（`class_ability_level`）もラン内。

## Phase 1 — 緊張と山場（退屈・単調に効く）

**目標**：初見の人が3〜4分で一度は死にかける。30〜45秒ごとに「来る！」と「凌いだ！」がある。

1. **サージを有効化して見せる**（`exploration_run.json` `surge.enabled: true`、既存の`map_run_controller.gd`の経路を確認）
   - 45秒・105秒・165秒・225秒（MAPごとにずらす）。発生10秒前にHUDへ「第N波 10秒前」と太鼓の音、画面の縁がレア度色ではなく朱赤に脈打つ。
   - 波の間は`spawn_interval ×0.6`・包囲湧き（画面外のリング状に一斉）。終了時に報酬（箱＝装備／回復／欠片）。既存`reward_sequence`を使う。
   - HUDの時計の下に「次の波まで」「ボスまで」を常時出す（**目標の可視化**）。
2. **敵に役割を持たせる**（`data/enemies/*.json`、`systems/wave_spawner.gd`のRoster比率）
   - 突撃型（速い・低HP・接触で削る）、壁型（遅い・高HP・ノックバック耐性、押し込まれると詰む）、
     遠距離型（弾で**立ち止まりを罰する**）、群れ型（小さく大量）。各波で主役を変える（例：第2波＝突撃型中心、第3波＝遠距離混在）。
   - 強敵（`strong_*`）の赤い予兆は既存。波の中盤に1体ずつ混ぜる。
3. **圧力曲線**：`enemy_hp_multiplier`を0.38→0.55、速度0.65→0.8から試す。序盤30秒は今のまま易しく、60秒で画面に常時12体以上。
   回復を絞る（75秒の箱の回復をなくし、回復は再生結界と撃破回復の強化頼みにする）。
4. **検証**：`tests/five_minute_survival_check.gd`に「60秒時点の画面内敵数≥12」「波の開始・終了イベントが4回」「無敵なし自動操作で3分以内に被弾HP50%以下が起きる」を追加。
   無敵つき通しはPASSでも「勝率の証明ではない」と明記（既存方針）。

## Phase 2 — スキルの可読性（分かりにくいに効く）

**目標**：カードを3秒見れば「いつ・何が・どれくらい・何と相性がいいか」が分かる。

1. **データ拡張**（`data/upgrades/*.json`、`resources/upgrade_data.gd`）
   ```json
   "trigger": "on_hit",            // on_hit / on_kill / every_n_hits / periodic / on_dodge / on_damaged / low_hp / passive
   "trigger_text": "攻撃を当てたとき",
   "effect_text": "近くの敵へ雷が渡る（最大2体）",
   "tags": ["雷", "連鎖", "命中"],
   "scales_with": ["attack_speed", "double_strike", "hit_count"],
   "numbers": {"chance": 1.0, "every_n": 3, "damage_pct": 0.35}
   ```
2. **発動をクールダウンから「命中N回ごと／確率」へ**（`survival_upgrade_effects.gd`）
   - 残影追撃：0.6秒CD → 命中3回ごと（段階で2回ごと）。雷光連鎖：0.7秒CD → 命中ごとに35%（段階で+15%）。
   - これで**攻撃速度・連撃・多重射撃が発動回数に直結**する（シナジーの土台）。威力は再調整。
3. **カードの定型**（`ui/level_up_select/`）：上段アイコン＋名前、中段3行固定「発動／効果／相性」、下段に動く比較（既存）。
   相性行は所持スキルのタグと`scales_with`を突き合わせ、噛み合う候補に「✦ 相性：雷光連鎖が増える」を**緑で**出す。
4. **HUDに「今のビルド」**：左上の強化石板（既存）に所持スキルのタグを小さく並べ、発動したスキルのピップが光る（何が働いているか分かる）。

## Phase 3 — シナジーと進化（組み合わせを考える楽しさ）

1. **連撃**（新規`survival_double_strike`：通常攻撃が確率で2回になる。段階で確率上昇）と**命中回数**系（既存の高速攻撃・多重射撃）を
   「発動回数を増やす側」として揃える。雷・影・範囲・貫通は「発動したときの内容」側。
2. **進化レシピ**（`data/upgrades/evolutions.json`、5〜6本から）
   - 雷光連鎖Lv3 ＋ 連撃Lv2 → **雷帝の連撃**：2回目の斬撃が必ず雷を呼び、連鎖先にも落ちる
   - 残影追撃Lv3 ＋ 高速攻撃Lv3 → **影走り**：影が自分で敵を追い、0.5秒ごとに斬る
   - 広域攻撃Lv3 ＋ 強撃Lv3 → **大断**：横薙ぎが画面幅、命中時にノックバック
   - 貫通射撃Lv2 ＋ 多重射撃Lv2 → **矢の雨**：扇状5本、貫通無制限
   - 再生結界Lv3 ＋ 雷光連鎖Lv2 → **帯電結界**：シールドが割れると周囲へ雷
   - 条件を満たすと次のレベルアップに**進化カードが必ず1枚**出る（橙の「進化」枠、秘技の「NEW!」枠の仕組みを流用）。
3. **候補の質**：3択＋リロール（金貨）＋「もう出さない」1回。所持スキルに空いている相性がある間は、1枚は相性カードを保証。
4. **秘技（arcana）との接続**：秘技も`trigger`（periodic）とタグを持たせ、「雷帝落雷×雷タグ＝落雷が連鎖」のように進化へ絡める。

## Phase 4 — 育成（1ダンジョンで終わらせない）

**目標**：「ステージを攻略 → 拠点で整える → より深いステージへ」の鎖。負けても何かが残る。

1. **装備の持ち越し**：`EquipmentComponent._on_run_ended`で消さず、`SaveManager`に`persistent_equipment`（装備6枠＋所持品上限20程度）を保存。
   拠点（`ui/home`）に鍛造を置き、欠片と金貨で合成・強化する（鍛造はラン中からも使えるまま）。
2. **職業の熟練**：`class_ability_level`をラン外へ累積（`SaveManager.class_mastery[character_id]`）。熟練で天賦図（既存は剣士だけ）の開放、
   初期スキル1つ持ち込み、初期装備枠。
3. **ステージの鎖**：MAP1→2→3を「深度」付きで繰り返す（既存`current_depth`・`difficulty_curve_id`を使う）。クリアごとに深度+1で敵倍率と報酬レアが上がる。
   HUDとホームに「深度・次の目標（到達／撃破／取得）」を出す（**何を目指すか**の可視化）。
4. **負けたときの持ち帰り**：撃破数と到達時間で欠片、装備は確率で1つ持ち帰り（ロック中は保証）。
5. **検証**：`survival_home_check`に「持ち越し装備がホームに表示され、次ランで装備されている」「熟練が累積する」「深度が上がる」を追加。

## 進め方の原則

- 1 Phaseごとに**遊んで判断**（クラウドでは手触りが見えない。ローカルのGodotで）。Phase 1だけでも体験は変わる。
- 数値は`data/`に寄せ、コードは発動の仕組みだけを持つ。進化レシピと相性はデータで増やせるように。
- 新要素の試作は最小実装にこだわらず、必要な範囲を作る（ユーザー方針）。仕様書とダッシュボードは節目で更新、`docs/codex_handoff.md`は毎回数行。
- 既存の検査（`script_load_check`、`five_minute_survival_check`、`equipment_merge_check`）は維持し、Phaseごとに1〜2個の実経路検査を足す。
