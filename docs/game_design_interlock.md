# VSGAME 成長設計 — 噛み合う構造への作り直し

## なぜ作り直すか

ユーザー評価は「絶望的につまらない」「徐々に強くなる実感がない」。

前案(カードを15枚足す)は**症状にしか触れていなかった**。本質的な問題は選択肢の数ではなく、
**すべてのシステムが並列に走っていて互いを参照していない**こと。

現状の構造:

```
属性     → 追加ダメージ + 副作用        （他と無関係）
Fusion   → ペアの辞書引きで大技         （他と無関係）
装備     → ステータス加算               （他と無関係）
職業     → 攻撃モーションの差           （他と無関係）
祭壇/宝箱 → たまに何かもらえる           （他と無関係）
```

ヒット作の構造(リサーチ結果):

- **Vampire Survivors**: 武器 × パッシブ → **進化**。パッシブは進化の鍵を兼ねる。
  毎回の選択に「今の効果」と「進化への前進」の二重の意味がある。
- **Brotato**: ステータスが武器の強さを決めるため、ステータス選択がビルドを収束させる。
- **Halls of Torment**: 特性がアビリティを、装備の接辞が特性を参照する。

**共通点: 選択肢が互いを参照している。**

---

## 中核となるモデル: 「状態」を全システムの共通通貨にする

新しい並列システムは足さない。**既にあるものを1本の軸へ結び直す。**

### 1. 属性は敵に「状態」を乗せる

| 属性 | 状態 | 既存実装 |
|---|---|---|
| 火 | **燃焼** | あり(`_burning_targets`、DoT+AoE) |
| 氷 | **凍結/鈍足** | あり(`slow` / `freeze`) |
| 雷 | **帯電** | 連鎖はあるが状態としては未実装 |
| 光 | **刻印** | Holy Strikeのカウンタはあるが敵側の状態ではない |
| 闇 | **呪い** | あり(`apply_curse`、被ダメージ増加) |

**この「状態」が、以降すべての参照先になる。**

### 2. 状態は目に見えなければならない(最優先)

現状、状態は数値としてしか存在せず**プレイヤーから見えない**。
見えない状態を参照する選択肢は、設計として成立しない。

敵に状態アイコンまたは色味を出し、**盤面が読める**ようにする。
これが無いと以降の全設計が機能しないため、最初に実装する。

### 3. 全システムが「状態」を参照する

```
                    ┌─────────────┐
        属性Lv ────→│   状態      │←──── 職業スキル(居合等)
                    │ 燃焼/凍結/  │
   強化カード ─────→│ 帯電/刻印/  │←──── 装備の接辞
                    │ 呪い        │
        Fusion ────→└─────────────┘
                           │
                           ↓
                    反応 / 進化 / 条件付きダメージ
```

具体的な参照の例:

- **条件付き強化**: 「燃焼中の敵への与ダメージ +25%」
  → 火を取った選択が、後の全ての攻撃の価値を変える
- **反応**: 燃焼中の敵に凍結が乗る → 蒸発(大ダメージ)
  → 2属性の組み合わせが瞬間ごとの手応えになる
- **職業の噛み合い**: 居合が燃焼中の敵を貫くと燃焼が周囲へ伝播する
  → 職業選択がビルドの意味を変える
- **装備の噛み合い**: 接辞「呪い中の敵に+X%」
  → 装備が属性ビルドの一部になる(現状は無関係な数値加算)
- **進化**: 属性Lv3 + その属性の強化カード3枚 → その属性の極大技が解放
  → 毎回の選択が到達点への前進になる(VSの進化と同じ役割)

**これは新システムの追加ではなく、既存システム同士の結線である。**
画面もリソースも増えない。増えるのは「意味」だけ。

## 設計する成長曲線の形

「徐々に強くなる」は**均一な傾き**ではなく、**踊り場のある階段**にする。

| 種別 | 頻度 | 体感 |
|---|---|---|
| 小: レベルアップの選択 | 30〜45秒 | 継続的な手応え |
| 中: 属性Lv2 / Lv3 | ラン数回 | 見た目が変わる |
| **大: Fusion成立 / 進化解放** | ラン2〜3回 | **画面が変わる。ランの山場** |

現状は「中」が6回あって終わり、「大」がFusion1回だけ、「小」が実質存在しない。
だから平坦に感じる。

## 実装フェーズ

依存関係があるため、この順で進める。**各フェーズ終了時に必ず遊べる状態にして止める。**

### A1: 基盤 — 状態の可視化 + XP曲線 + 条件付き強化

**これが無いと以降が成立しない。最優先。**

1. **XP曲線の実測と調整**: レベルアップが来なければ全て無意味。
   ラン全体で30〜45秒に1回を目標に測定・調整する。
2. **5状態の統一と可視化**: 雷の「帯電」と光の「刻印」を敵側の状態として実装し、
   既存の燃焼/凍結/呪いと合わせて5つに揃える。敵に状態が見えるようにする。
3. **状態を参照する条件付き強化カード**: 「燃焼中の敵への与ダメージ+25%」型。
   所持属性に応じて出現する。
4. **属性強化カード(既存値の増幅)**: 連鎖+1、燃焼時間+50%など。
   `element_combat.json`の値に係数を掛けるだけで実装できるもの。

→ この時点で「選んだ属性が深まり、選択が後の攻撃の価値を変える」状態になる。

### A2: 反応 — 2属性が噛み合う

同一の敵に2つの状態が乗ったときに反応が起きる。
**既存の`fusions`定義10組をそのまま反応表として使う**(2属性しか持てないため、
1ランで成立する組は必ず1つ = 既存データと1対1で対応する)。

現在Fusionは「周期的に発動する大技」だが、これを**瞬間ごとの反応**にも広げることで、
戦闘中ずっと2属性の組み合わせを感じられるようにする。

### A3: 進化 — 選択の到達点

条件: 属性Lv3 + その属性の強化カードN枚 → その属性の極大技が解放。

VSの進化と同じ役割。**毎回のカード選択が「今の効果」と「進化への前進」の二重の意味を持つ**
ようになり、選択の重みが変わる。

既存の「完成大技(5種)」を進化の受け皿として流用できる可能性が高い。新規に作らないこと。

### B: 装備を属性ビルドへ接続する(別タスク)

自動回収・自動装備でラン中の摩擦を除去した上で、**接辞が状態を参照する**ようにする。
「呪い中の敵に+X%」「燃焼を延長する」など。装備が独立した数値加算でなくなる。

### C: 手作りMAP(別タスク)

レイアウトは設計側(Claude)がテキストグリッドで作成し、Codexはローダーを実装する。

---

## この設計で守ること

1. **新しい並列システムを作らない。** 追加するのは既存システム間の参照だけ。
   画面・通貨・管理UIを増やさない。
2. **見えない強化を作らない。** 選んだ結果が画面に出ること。
   `+5%ダメージ`を並べても成長実感は出ない。
3. **敵の1発ダメージを上げない。** 緊張は密度と状態で作る。
   リサーチで最も嫌われたのは「理由のわからない即死」。
4. **面白さは数値で測れない。** 各フェーズ終了時に遊べる状態で止め、
   ユーザーの体感評価を得てから次へ進む。
